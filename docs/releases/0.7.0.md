# Omascribe 0.7.0

Omascribe continues Omawrite's version sequence with a local harness for developing,
testing and controlling the editor. It keeps Qt 6, Qt Quick, qmake and C++17.

## Application and packaging

- Rename the application, executable, launcher, icon and Arch package to
  `omascribe`, version 0.7.0-1. Omascribe has separate settings, recovery data and
  local communication, so it can coexist with the original Omawrite package.
- Keep the original license notices and bundled IBM Plex Mono font license.
- Add a shared application version and a headless `omascribe --version` command.
- Document installation from a development checkout and stable release packaging.
  Existing Omawrite preferences and drafts are not automatically imported.

## Local development harness

- Add `bin/harness check` to build and test in isolated profiles and preserve a
  JSON report, QtTest results, logs, screenshots and document state.
- Add `bin/harness run` with reusable profiles, deterministic themes and text
  scale, and optional offscreen rendering for experiments and crash recovery.
- Load the shipped QML resources and fonts in tests. Share initialization with
  the app, reject unexpected QML warnings and fix the shortcuts dialog binding loop.
- Document architecture, document rules, executable control examples and completion
  checks in `AGENTS.md` and the repository guides.

## Local JSON control and document protections

- Expose each window through a private same-user Qt local socket. Discover windows
  and send one JSONL version 1 request through the app's own control client.
- Read unsaved Markdown, selection, cursor, file, undo/redo, conflicts and UI state.
  Select and replace ranges, undo/redo, open, save, save as, reload, resolve external
  changes, close and capture the actual window as PNG.
- Share transitions between QML and control through `EditorSession`. Require the
  current session version for mutations; reject stale requests without applying them.
- Validate UTF-16 ranges, preserve surrogate pairs, normalize line endings and make
  each replacement one undo step. Preserve the prior behavior where undo to saved
  text can still leave the document marked modified.
- Protect dirty drafts, pre-read a replacement before discard, cancel pending
  transitions after failed saves and check disk contents before overwriting.
- Handle equivalent paths and symlinks, external edits and deletions, explicit
  overwrite permission, pending dialogs and recovery after forced termination.
- Limit messages to 16 MiB and connections to five seconds. Do not automatically
  retry uncertain mutations. Acknowledge close before the window terminates.

## Release workflow

Every release must update application, PKGBUILD and README versions together and
publish the matching AUR package. The harness rejects version drift and provides
`prepare-aur` to generate a standalone PKGBUILD, `.SRCINFO`, install script and
source checksum from the immutable GitHub tag archive. Packaging fixes require
a `pkgrel` bump and retain the original source archive.

The 0.7.0 AUR recipe is prepared and locally verified. AUR publication is pending
creation of the maintainer's AUR account and registration of an SSH public key.

## Verification and installation

The local harness passes 39 QtTest results and seven release workflow tests, with
no unexpected QML diagnostics. It records six screenshot/state pairs covering
light/dark themes, the minimum window at 4/3 text scale, search, unsaved changes
and external conflicts. A standalone Arch package is built from the published
tag archive and checked with a real JSON edit/save/screenshot/close flow.

From a checkout, run `bin/install` as your ordinary user to build and install
through makepkg and pacman. GitHub pushes alone do not update installed packages;
published AUR versions become available to Omarchy's package update step once
the AUR package exists. See [the packaging guide](https://github.com/RolandDumit/omascribe/blob/v0.7.0/docs/packaging.md).

Native portals, printing, IME, desktop focus and physical monitor fractional
scaling still require manual desktop verification. The automated 4/3 fixture
checks text scale rather than the compositor's monitor scale.
